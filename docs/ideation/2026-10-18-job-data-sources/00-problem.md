# 문제 정의: 공고 데이터를 어디서, 어떻게 받을 것인가

작성: 2026-10-18 · 오케스트레이터(Opus 5.5) · 아이디어 회의의 기준 문서

## 1. 사용자와 해야 할 일

- **사용자:** 신입 구직자 1명(본인). 예시 희망 직무는 시스템엔지니어, 서버 운영, 인프라, 리눅스, SM(설계 문서의 예). 지역과 관심 기업은 아직 미정.
- **해야 할 일:** 내 조건에 맞는 신입 공고를 **매일, 놓치지 않고** 받아 보고, 왜 추천·탈락했는지 근거를 확인한 뒤 지원 여부를 정한다.
- **지금의 고통:** AI 채팅으로 찾으면 첫 페이지만 보고 끝나고, 기준이 일관되지 않으며, 왜 빠졌는지 기록이 없다(설계 문서 "해결할 문제").

## 3. 문제 문장

> **포털의 승인이나 무단 수집에 기대지 않고, 신입 구직자 1명이 자기 조건에 맞는 공고를 매일 충분히 넓게, 정당하게 받으며, 무엇을 놓쳤는지 알 수 있게 하려면 어떻게 해야 하는가?**

어떻게 하면(HMW) 질문으로 나누면:

1. 포털을 거치지 않고 **공고의 원래 주인(기업, 공공기관)** 에게서 직접 받을 수 있는가?
2. 개인에게 **열려 있는 공식 창구**(공공데이터, 알림 메일, 공개 피드)는 무엇이 있는가?
3. 단일 소스가 전부를 갖지 못할 때 **"빠짐없이"를 어떻게 정의하고 측정**하는가?
4. 사용자가 이미 하는 행동(포털 검색, 메일 확인)을 **수집 경로로 바꿀** 수 있는가?

| 자동화 | 매일 사람 손 없이 돌 수 있나? |
| 구현·유지 비용 | 1인이 만들고 유지할 수 있나? 사이트 개편에 얼마나 약한가? |
| 기존 구조 적합성 | 지금의 어댑터 계약(app/adapters/base.py)과 수집 엔진에 끼울 수 있나? |
