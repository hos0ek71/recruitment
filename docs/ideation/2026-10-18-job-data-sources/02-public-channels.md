# 개인이 쓸 수 있는 공공·공식 채용 데이터 경로

조사일: 2026-10-18 · 아이디어 회의 B · 읽은 기준: `AGENTS.md`, `00-problem.md`, `docs/harness/progress.md`, `docs/research/03-mvp-external-fact-check.md`.

## 1. 결론과 판정 기준

**문서상 지금 신청·구독 가능한 경로는 보수적으로 7개다: 공공데이터포털 REST API 4개, 대학 공식 RSS 2개, 잡알리오 맞춤 알림 1개.** API 4개는 개발계정 신청 가능 기준이며, 키 발급·실제 채용 API 응답까지 검증한 수가 아니다. 잡알리오 알림은 RSS/API와 별개인 수신 경로로 셌다. 연간 과거자료, 고용24 3종, 사람인, 경기 민간 채용정보는 이 수에서 제외했다.

**최우선 신청은 재정경제부 공공기관 채용정보 조회서비스(잡알리오 계열)**다. 신입 여부·NCS·지역·기간 필터와 총건수·원문 링크가 있어 현재 수집 엔진에 가장 명확하게 대응한다. 공공기관 취업을 원한다는 사용자 결정은 아직 없으므로, 이는 데이터 확보 실험의 우선순위이지 민간 SE·인프라 전체를 대체한다는 제안이 아니다.

- **확인:** 공식 공개 문서·명세 또는 공개 RSS 응답에서 확인했다.
- **추론:** 공공데이터포털의 일반 개인회원 신청 체계와 해당 REST API의 자동승인·이용제한 없음에서 개인 신청 가능을 판단했다. 개별 계정의 발급 성공을 보증하지 않는다. 제공기관 별도 키가 필요한 LINK형에는 이를 적용하지 않았다.
- **확인 못 함:** 자료가 없거나 공개 열람만으로 알 수 없다. 미확인을 불가·0%·무제한으로 바꾸지 않았다.
- 신입 비중, IT 비중, 신입 IT의 교집합 비중, 국내 전체 SE·인프라 대비 포함률은 서로 다르다. 이번에는 공고를 대량 조회하지 않았으므로 **모든 경로에서 정확한 비율은 확인 못 함**이다.

공공데이터포털 이용은 회원가입·인증키·API별 활용신청을 거친다([행정안전부 이용안내](https://mois.go.kr/frt/sub/a02/openInfo_2/screen.do)). 자동승인은 담당자의 개별 확인 없이 신청 즉시 활용하는 방식이라는 공식 설명이 있으나, 다른 기관의 승인 처리기간·한도를 본 API에 옮겨 적용하지 않았다([공정위 절차 설명](https://www.fairdata.go.kr/ext/data/openApiGuidance.do)).

## 3. 공공 API에서 실제로 검색·필터할 수 있는 것

아래는 인증 없이 공개된 페이지 안의 Swagger 명세를 읽은 결과다. 실제 API 엔드포인트는 호출하지 않았다.

### P1: 공공기관 공고를 먼저 완주하는 실험

- 목록 `/list`, 상세 `/detail`. JSON/XML, `pageNo` 기본 1, `numOfRows` 기본 10, 응답 `totalCount`가 있다.
- 검색: `recrutPbancTtl`(제목 부분일치), `recrutSe`(채용구분), `ncsCdLst`, `workRgnLst`, `hireTypeLst`, `acbgCondLst`, 기관분류·유형·코드, 진행 여부, 대체인력 여부. 코드 값은 별도 코드정의서로 확인해야 하며 이번에는 코드 번호를 추정하지 않았다.
- `pbancBgngYmd`와 `pbancEndYmd`는 둘 다 **채용공시 시작일 기준 검색 구간**이다. 두 번째 것을 공고 마감일 필터로 해석하면 안 된다.
- 응답: `recrutPblntSn`(ID), 제목·기관, 채용구분명·NCS명·근무지역·학력·고용형태, 채용인원, 자격 내용, 공고 시작·종료일, `srcUrl`. 첨부·전형은 상세에서 보강한다.
- 신입·IT 비중은 확인 못 함. **추론:** 채용구분과 NCS를 제공하므로 공공기관 신입 IT 후보를 코드로 좁히기 좋다. NCS 정보통신과 SE·리눅스 운영은 같은 범주가 아니므로 제목·자격·직무기술서를 추가 확인해야 한다.
- 완전성은 선택한 공공기관 API 쿼리 안에서 총건수와 고유 ID를 대조하는 수준이다. 공공기관 원공고 누락이나 시장 전체 누락까지 증명하지 않는다. [근거: P1 공식 명세](https://www.data.go.kr/data/15125273/openapi.do)

### P2: 나라일터의 최신 공고와 연간 자료를 분리

- `/getList`: `Pblanc_ty`(공개경쟁·경력경쟁·계약직·행정지원인력·공모직위), `Instt_se`(국가·지방·공공기관·교육청), `Instt_nm`, `Kwrd`, `Begin_de/End_de`(등록일), `Sort_order`, 페이지·건수.
- `/getItem`, `/getItemFile`, `/getItemPosition`으로 상세·첨부·선발직위를 나눈다. 기관·직급 목록 API도 있다. 응답은 XML이다.
- 공개 응답 스키마의 상세 필드·총건수 명칭은 후속 실제 계약 검증에서 확정한다. 신입이라는 단일 필터는 이번 명세에서 확인 못 함. **공개경쟁채용은 민간기업의 신입 채용과 동일하지 않다.** 전산직 시험·자격 요건과 일반 신입 SE 구직을 구별해야 한다.
- P5의 2024년 연간 파일은 ID·기관·제목·접수기간·직급·인원 등을 제공하지만 최신 일일 수집용으로 쓰지 않는다. 신입·IT 비중은 두 자료 모두 확인 못 함. [최신 API](https://www.data.go.kr/data/15156780/openapi.do), [연간 자료](https://www.data.go.kr/data/15151560/fileData.do)

### P3·P4: 지방·지역 공고 보완

- P3 `/openXmlEmployInfo`: 명세상 검색 인자는 `sidoCd`, `type`(XML)이며 페이지·직무·신입 필터는 없다. 응답 `totalCount`, `NO`, `UPD_DATE`, `URL`, `ENT_RECRUIT`, `EMPLOY_GB`, `DUTY_DETAIL`, 연봉·근무지·접수기간·지역제한·자격증 등이 있다. **추론:** 시도별 일괄 응답을 로컬에서 필터할 수 있으나, 페이지가 없다고 무제한·전국 완전 반환을 보장하는 것은 아니다. 응답 상한·시도 미지정 의미는 실제 계약 확인 과제다. 신입·IT 비중 확인 못 함. [P3 명세](https://www.data.go.kr/data/15159757/openapi.do)
- P4 검색: 유형 `type`, 제목 `sj`, 시작·종료 검색일 `srch_bgn_dt/srch_end_dt`, 접수 여부 `rcpt_yn`, 페이지·건수. 응답: `totalCount`, 번호·유형·제목·인원·부서·접수일·내용 `cn`. 합격자발표가 섞이며 전용 신입·IT 필터와 원문 URL은 공개 출력표에서 확인 못 함. **추론:** 지역이 용인으로 정해졌을 때만 보완 가치가 높고, 임기제 등 경력성 공고도 많을 수 있다. 실제 비중 확인 못 함. [P4 명세](https://www.data.go.kr/data/15097328/openapi.do)

## 4. 고용24 개인용 3종: 공채속보는 유력하지만 승인·범위를 분리

`00-problem.md`에는 사용자가 신청 화면에서 개인회원의 채용행사·공채속보·공채기업정보 신청 가능을 확인했다고 기록되어 있다. 반면 공개 [소개 페이지](https://www.work24.go.kr/cm/e/a/0110/selectOpenApiIntro.do)는 여전히 기업회원 전용·담당자 심사를 안내한다. 따라서 **개인 3종 신청 가능은 세션 내 사용자 확인 근거**, 명세의 기능·필드는 공식 공개 문서 근거로 구분한다. 로그인해서 추가 확인하거나 신청하지 않았다.

## 6. API 밖의 정당한 경로

1. **잡알리오 공식 알림:** 정부 운영 앱이 맞춤조건 등록 후 푸시·이메일 제공을 명시한다. 사용자에게 직접 전달되는 경로다. 수신함 연동·메일 본문 영구 저장은 이번에 이용조건을 확인하지 않았으므로 별도 결정이다. 앱으로 받는 단계만으로도 수집기 구현 전 효용을 얻을 수 있다. [공식 앱 설명](https://play.google.com/store/apps/details?hl=ko&id=com.moef.jobalio)
2. **대학이 공개한 RSS:** 부산대 컴퓨터공학 채용게시판과 고려대 세종 일반채용 게시판은 공식 RSS 링크를 제공한다. 두 피드를 각각 1회 열어 HTTP 200·RSS XML·50개 항목과 `title/link/description/pubDate/author`를 확인했다. 공개 피드 구독 목적에 맞게 제목·링크·발행일 중심으로 쓰고, 피드에 없는 첨부파일·게시판 전체를 자동 수집하는 허가로 확대하지 않는다. 대학 추천채용의 지원 자격은 재학생·졸업생 여부 등에 따라 원문에서 별도 확인한다. [부산대 RSS](https://cse.pusan.ac.kr/bbs/cse/2060/rssList.do?row=50), [고려대 RSS](https://cwms.korea.ac.kr/bbs/cdc/526/rssList.do?row=50)
3. **기업·포털 RSS:** 이번에 일반 개인이 구독할 수 있는 국내 기업·대형 채용포털의 현행 채용 전용 RSS를 구체적으로 확인 못 함. 존재한다고 가정하거나 임의 RSS URL을 만들지 않는다. 정책브리핑은 오히려 공식 사이트에 RSS 제공 중단 안내가 노출되어 대체 피드로 권하지 않는다([공식 사이트](https://m.korea.kr/index.jsp)).
4. **경기도 민간 채용 API 재개방:** 공식 교육데이터 연계 설명은 워크넷 공고 중 동의 기업의 경기 민간 채용 데이터를 소개한다. 공급자 공개 페이지는 이번 텍스트 열람에서 기본정보 이후 명세를 확인하지 못했다. 개인 키·갱신·원문 URL·현재 제공 지속 여부가 확인되면 민간 범위 보완 가치가 크지만, 고용24 개인 제한을 우회하는 수단이라고 단정하지 않는다. ## 9. 검증 기록과 남은 문제

- web 검색·공식 페이지 열람 및 Python 표준 라이브러리로 공개 HTML의 명세를 읽었다. 고용24 탭은 페이지에 공개된 `fn_tabChange` ID를 사용했고 API 데이터 호출은 하지 않았다.
- web 도구의 고용24 세부 탭·RSS 열람이 실패해 같은 공개 URL을 인증 없는 Python GET으로 열었다. 두 RSS는 HTTP 200·XML 파싱·각 50항목을 확인했다.
