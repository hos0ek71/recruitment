1. **Open API는 약관이 개인·일반 기업·프로젝트·개인 사용·DB 수집을 명시적으로 거절한다.** 개인 사이트 공개·목적 기재·IP 등록으로는 못 넘고, 개인사업자 등록도 "일반 기업"이라 달라지지 않는다. [J2 제5조 ④, 확인 2026-10-20]
2. **승인돼도 우리 제품 설계와 충돌한다.** 같은 약관 제7조가 가공·복제·저장, 합의되지 않은 사이트 사용, 과금·영업을 금지하므로 `raw_posting` 저장·필터·AI 평가 구조가 성립하지 않는다. [J2 제7조 ③④⑤]
3. **데이터·API·MCP를 개인에게 여는 공식 상품은 확인 못 함.** 제휴 문의 페이지는 데이터·API 유형을 적지 않았고, 공식 MCP·플러그인도 없다. 있는 MCP는 같은 그룹 ATS "나인하이어"의 기업 엔터프라이즈용이다. [W1·N2]
4. **robots.txt의 AI 검색·인용 에이전트 허용은 의사 표시일 뿐 이용 허락이 아니다.** 허용 대상은 식별된 에이전트의 공개 콘텐츠 열람·인용이고, 저장·재가공·일일 장부를 허락하는 문구는 없다. 개인회원 약관은 여전히 사전동의 없는 복제·제공을 금지한다(추정 포함). [J3·J4 제18조 ④]
5. **정식으로 열 수 있는 길은 "서면 사전동의 요청" 1건이 유일한 후보다.** 성공 가능성은 낮다(추정). 확인되는 허락 경로는 0개이므로 이를 전제로 한 설계는 지금 권하지 않는다.

# 01. 잡코리아와 정식 관계를 맺는 경로 (발산 1)

작성: 2026-10-20 · 회의 워커 A · 모든 외부 사실의 확인일은 **2026-10-20**이다. "추정"은 확인된 사실에서 끌어낸 판단이고 "확인 못 함"은 찾지 못했다는 뜻이지 없다는 단정이 아니다.

## 조사 범위와 방법

- 잡코리아 공고 목록·상세·검색 결과·sitemap을 요청하지 않았다. 공고 데이터는 한 건도 받지 않았다.
- 계정 생성, 로그인, 문의 발송, API 신청, 제휴 이메일 발송을 하지 않았다.
- `curl`로 원문을 직접 받은 것은 API 신청·약관 페이지, 개인회원 약관, robots.txt 3건과 `llms.txt` 1건(404)뿐이고 각 1회 요청했다. UA 문자열에 연구 목적을 적었고 AI 에이전트 UA를 사칭하지 않았다.
- 나머지 페이지는 웹 읽기 도구의 요약을 거쳤다. 아래 표의 근거 열에 **원문 확인**과 **요약 경유**를 구분했다. 요약 경유 항목은 조 번호·수치를 원문과 대조해야 한다.
- 뉴스는 대부분 검색 결과 요약만 봤다. 근거 열에 "검색 요약"이라고 표시했다.

신입공채 API의 건수 설명은 표(500개)와 FAQ(사이트와 같은 수)가 어긋난다. 어느 쪽이 맞는지는 확인 못 함이다. [J1, 요약 경유]

**개인사업자 등록이 바꾸는가:** 바꾸지 않는다고 본다. 제5조 ④는 "일반 기업"도 거절 대상이고, 신청서의 "기업" 구분도 내부 검토 후 미승인될 수 있다고 적는다. 목적 거절 사유(프로젝트·개인 사용·DB 수집)는 사업자 여부와 무관하다. 사업자 등록을 목적으로 신청서를 거짓으로 꾸미는 것은 제5조 ③이 승낙 거부 사유로 둔 "허위 기재"에 해당할 수 있다. [J2, 일부 추정]

**승인돼도 쓸 수 있나:** 못 쓴다. 제7조 ④가 저장을 막으므로 `raw_posting` 보관(AGENTS.md 불변식)과 일일 장부, 필터 탈락 사유 기록이 약관과 충돌한다. 진행 중 공고만 내려와서 마감·삭제 이력도 남길 수 없다(추정). 약관 예외를 서면으로 받지 않는 한 불가다. [J2·AGENTS.md]

### robots.txt(2026-08-21판)의 "사용자 요청형 AI 에이전트" 허용

**원문 확인.** 파일 머리: `Version: 3.0 / Desktop`, `Last updated: 2026-08-21`, `Author: WS SHIN`. 정책 주석은 "AI 학습 크롤러와 AI 검색·인용 크롤러를 분리한다"이고 근거 문서 `JK_robots_txt_notes_v3.0.md`는 내부 자료라 공개되지 않았다. [J3]

| 구간 | 대상 | 규칙 |
| --- | --- | --- |
| AI 학습 | GPTBot, ClaudeBot, anthropic-ai, Claude-Web, Google-Extended 등 22종 | `Disallow: /` |
| AI 검색·인용 | OAI-SearchBot, **ChatGPT-User**, **Claude-User**, Claude-SearchBot, MistralAI-User, DuckAssistBot, YouBot, GoogleOther, xAI-Grok, Grok-DeepSearch | 로그인·`/User/`·`/My/`·`/Account/`·`/RecrtMng/`·`/Corp/`·`/Text_co/`·`/Salary/mylist`·`/Recruit/JobList/SpaceClick`만 차단. `/User/Qstn/AnswerWrite`, `/User/Qstn/Index`는 허용(Q&A) |
| Perplexity | PerplexityBot, Perplexity-User | 위와 같은 Disallow 전용 |
| 스크래퍼 | CCBot, Diffbot, Scrapy, DataForSeoBot 등 | `Disallow: /` |
| 소셜 미리보기 | facebookexternalhit 등 | `/Search/`, `/search/` 차단 |
| 국내 검색엔진·`*` | Yeti, Daumoa, 그 외 | 위 차단 목록과 같음(`/Search/`는 차단 안 함) |

**읽는 법:**

1. 허용은 "공개 콘텐츠만"이라고 되어 있고, `/Recruit/`·`/Search/` 같은 공고 경로는 AI 검색·인용 에이전트에 차단돼 있지 않다. 그래서 공고 열람은 이 에이전트들에게 *robots 수준에서는* 막혀 있지 않다. [J3, 파일에서 직접 읽은 사실]
2. 파일의 목적은 **인용·유입 유지**로 읽힌다. Perplexity 주석이 "추천 유입이 급감한 2025-02-11 사건"을 적고 있다. 가져가서 장부를 만드는 용도에 대한 언급은 없다. [J3, 추정]
3. **허락인가 의사 표시인가: 의사 표시다.** 근거는 셋이다.
   - robots.txt에는 라이선스·이용 조건 문구가 없고 약관을 참조하지 않는다. [J3]
   - RFC 9309는 robots 규칙이 접근 권한 부여 수단이 아니라고 명시한다. [06 문서 S3 재인용, 이번에 RFC 원문은 다시 열지 않음]
   - 개인회원 약관 제18조 ④는 "서비스를 이용하여 얻은 정보를 회사의 사전동의 없이 복사, 복제, 번역, 출판, 방송 기타의 방법으로 사용하거나 타인에게 제공할 수 없다"고 한다. robots.txt 허용이 이 사전동의를 대체한다는 문구는 없다. 다만 이 조항은 **회원**의 의무이고, 비회원 에이전트에 계약이 미치는지는 확인 못 함(추정: 계약은 못 미치나 부정경쟁·DB권 문제는 별개). [J4 원문 확인]
4. 법적 맥락: 잡코리아 대 사람인 사건에서 법원은 잡코리아가 "신원을 밝히고 출처를 표시하는 정상적인 검색로봇만 선별적으로 허용했다"고 보았고, 사람인이 VPN으로 IP를 분산하고 신원을 숨기고 robots.txt를 확인하지 않은 점을 문제 삼았다고 보도됐다. 법원명·선고일은 기사에 없다. [N3, 2016-02-22 기사 원문 열람] 즉 **식별되는 에이전트의 선별 허용**은 잡코리아가 법적으로 의미를 두는 사실이다. 우리가 그 에이전트가 아니라면 그 허용에 올라탈 수 없다(추정).
5. 에이전트 쪽 약속도 다르다. Anthropic은 Claude-User가 robots.txt를 따른다고 쓴다. OpenAI는 ChatGPT-User가 자동 크롤링에 쓰이지 않으며 사용자 시작 동작이라 robots 규칙이 적용되지 않을 수 있다고 쓴다. 잡코리아가 두 이름을 같은 목록에 넣은 것은 두 쪽의 차이와 무관한 일괄 선언으로 보인다(추정). [A1·O1, 요약 경유]

**우리 프로젝트에 대한 의미:**

| 사용 방식 | 판단 |
| --- | --- |
| 사용자가 claude.ai·ChatGPT에서 특정 페이지를 직접 물어봄 | robots 선언의 대상 범위 안(추정). 하지만 결과를 장부로 쌓는 일이 아니라 일회성 열람이다. 제품 수집 수단이 아니다 |
| 우리 서버가 Claude-User·ChatGPT-User UA를 달고 요청 | **UA 사칭이다.** 사람인 사건의 "신원 은닉" 요소와 같은 방향이라 위험하다(추정). 하지 않는다 |
| 우리 서버가 LLM API로 페이지를 읽게 함(도구 호출) | 에이전트의 UA와 robots 준수가 제공사 구현에 달려 있다. 이 문서에서 확인 못 함. 현재 불변식이 자동 브라우징 수집을 금지하므로 범위 밖 |
| 사용자의 예약 작업이 매일 열람 | "자동 크롤링이 아님"이라는 OpenAI 문구와 충돌할 여지가 있다(추정). 불변식상 금지 |

결론: robots.txt는 "AI 검색·인용 에이전트가 공개 콘텐츠를 보러 오는 것을 막지 않는다"는 정책 표시다. 저장·재가공·일일 수집을 허락한 것으로 해석할 근거는 없다. 해석이 갈리는 부분은 변호사 확인이 필요하다.

## 법적 맥락 (참고, 법률 자문 아님)

- **잡코리아 대 사람인:** 법원이 사람인의 크롤링을 부정경쟁행위로 판단했다. VPN으로 IP 분산, 신원 은닉, robots.txt 미확인, 출처 없는 대량 복제가 문제로 지목됐다. [N3, 원문 열람] 데이터베이스권 침해로도 보았다는 보도는 검색 요약에서만 확인했다. 2018년 합의 보도에는 합의금 120억 원이 있다. [N4, 검색 요약, 원문 미열람]
- **야놀자 대 여기어때:** 형사는 대법원 2021도1533에서 무죄가 확정됐고, 민사는 손해배상이 인정됐다는 취지의 보도가 있다. 공개 정보 크롤링의 형사 책임과 민사 책임이 다르다는 점을 보여준다. [검색 요약, 판결문 미열람: https://bizhankook.com/articles/27377.html]
- **적용:** 이 회의 제약(자동 수집 금지)은 법 위반 여부와 별개로 정해졌다. 위 사례는 "무허락 대량 수집은 실제로 소송과 합의로 끝난 적이 있다"는 점에만 쓴다. 개인 1명의 소량 열람에 같은 결과가 나온다는 근거는 없다(확인 못 함).

### 경로 4 제안서에 들어갈 내용 (초안 구성, 발송하지 않음)

사용자가 결정할 일이므로 틀만 적는다.

1. 신청자: 개인, 비영리, 사용자 1명, 판매·공유 없음.
2. 요청: 개인회원 약관 제18조 ④에 따른 사전동의(복제·저장 범위).
3. 범위: 신입·IT 직무 공고, 하루 1회 이하, 상세는 원문 링크로 이동, 지원은 잡코리아에서만.
4. 저장: 공고 메타데이터 보관 기간, 마감 공고 처리, AI 입력 여부(LLM 외부 전송 포함) 명시.
5. 질문: 개인이 쓸 수 있는 공식 데이터 경로가 있는지, 없다면 사용 가능한 공식 화면 기능.

## 이미 닫힌 길과의 관계

잡코리아 RSS(2014-06-25 종료), 붙여넣기 체크리스트, 부천대 경로, 에이전트 자동 브라우징은 다시 제안하지 않았다. Open API는 이전 문서의 "개인 거절 가능" 수준에서 **약관상 명시 거절 + 저장 금지 조항**으로 근거를 구체화했다. 고정 IP는 필수 요건이 아니라 호출링크 IP 바인딩이라는 점을 바로잡았다.

## 남은 문제

- 개인회원 약관 비회원 적용 범위, 사용자 요청형 에이전트를 통한 반복 열람의 위법성은 확인 못 함이다.
- 제휴 매체 목록의 위치, 신입공채 API의 건수 상한(표와 FAQ 불일치), 커리어 에이전트 출시 여부, 기술 블로그의 API·MCP 글은 확인 못 함이다.
- 요약 경유 항목(기업회원 약관 제9조, 제휴 문의 페이지 담당자 목록, Anthropic·OpenAI 문서)은 원문 대조가 필요하다.
- 이 문서에서 다룬 `worxphere.ai` 제휴 문의 담당자 이메일은 공개 안내에서 옮긴 것이며 유효성은 확인하지 않았다.
