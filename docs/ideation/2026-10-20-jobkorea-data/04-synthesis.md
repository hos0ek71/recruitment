## 한 줄 결론

잡코리아가 허락한 경로는 확인된 것이 0개다. Open API 약관이 개인·프로젝트·개인 사용·DB 수집을 명시적으로 거절한다(코디네이터가 원문 직접 확인). 현실적인 다음 수는 사람인 키가 나오면 "사람인이 잡코리아 공고를 얼마나 덮는지"를 재서 공백의 크기부터 아는 것이다.

## 권고 순서

1. **사람인 키 → 커버리지 실험 (02 문서 9절).** 공백이 작으면(예: 잡코리아 샘플의 80% 이상을 사람인이 가짐) 잡코리아 문제는 사실상 닫힌다. 실제 API 호출이라 사용자 승인 후 실행.
2. **공백이 크면 사용자가 둘 중 하나를 고른다.**
   - (가) 잡코리아에 서면 사전동의 요청(웍스피어 helpdesk). 비용 0, 성공 가능성 낮음.
   - (나) 위험을 감수한 소량 자동 수집. AGENTS.md 불변식 변경이 필요하고, 03 문서 8절의 조건(하루 1회 목록만, 비로그인, 정직한 사용자 에이전트, 차단 신호 시 정지·자동 재개 금지, 비공개 보관과 보관 기간, LLM 전송 범위 결정, 1인 전용이 깨지면 재심사)을 먼저 정한다. 오케스트레이터 권고는 (가) 또는 현상 유지.
