# 계획: 회사 분석과 자기소개서 맞춤 수정 (단계 5 제안)

작성: 2026-10-22 · 오케스트레이터(Opus 5.5) · 근거: docs/research/10(회사 정보 출처), docs/research/11(자소서 수정 설계), Orca Run `run_79b1bad9846a` 워커 2명(codex gpt-6.1-sol medium)

상태: **2026-10-22 사용자 승인(추가, MVP 이후, 개인정보 마스킹 전제 외부 AI 전송). features.json 단계 5에 반영. 결정 4·5·6은 미정(docs/mvp-design-review.md 0-3절).**

## 1. 목표

추천 공고 하나를 고르면, 그 회사와 모집 단위를 출처 있는 사실로 정리하고, 사용자의 **실제 경험만으로** 자기소개서 문항을 그 회사·직무에 맞게 고친 초안을 문장별로 검토하게 한다.

한 줄 원칙: **글은 AI가 다듬되, 모든 주장은 "내 원문 경험" 또는 "출처 있는 회사 사실"에 연결된다. 연결 안 되는 문장은 표시하고 검토 완료로 넘기지 않는다.**

## 2. 사용자 흐름

1. 추천 목록에서 공고를 고르고 [이 회사에 지원 준비]를 누른다.
2. **회사 분석 카드**를 확인한다. 공고 원문의 담당 업무·필수/우대 기술, 금융위원회 기업기본정보(업종·주요사업·설립·종업원), 공시 회사면 DART 사업보고서 요약이 출처·확인일과 함께 나온다. 비어 있는 칸(인재상, 기술 스택 등)은 "확인 못 함"으로 보이고, 사용자가 회사 홈페이지에서 본 사실을 짧은 메모+URL로 채울 수 있다.
3. **문항을 넣는다.** 회사의 실제 문항, 글자 수 제한(공백 포함 여부), 그 회사의 AI 사용 규정(허용/금지/모름)을 입력한다.
4. **경험 은행을 확인한다.** 처음 한 번 자소서에서 경험을 STAR(상황·과제·행동·결과)로 뽑아 사용자가 확인한다. 원문에 없는 결과·수치는 빈칸과 질문으로 남는다.
5. **초안을 받는다.** 문항마다 원문과 수정안이 나란히 나오고, 문장마다 바뀐 이유·연결된 경험·회사 근거 링크·경고(근거 없음, 모순, 확인 필요)가 붙는다.
6. **문장별로 수락·거절·직접 수정**한다. 수락할 때마다 글자 수·다른 회사명 잔존·근거 연결을 다시 검사한다.
7. 근거 없는 문장이 남아 있지 않으면 **검토 완료본**으로 저장하고 복사한다. 앱은 대신 제출하지 않는다.

## 3. 데이터 출처 (docs/research/10)

| 순위 | 출처 | 쓰는 곳 | 상태 |

| 4 | 고용24 공채기업정보 | 기업소개·주요사업 | 공채속보와 함께 신청한 개인 API, 발급 대기 |
| 5 | 사용자 사실 메모 | 인재상·기술 스택 등 빈칸 | 홈페이지를 앱이 긁지 않음. 사용자가 확인한 사실을 짧게 |
| 제외 | 뉴스 검색 API | 최근 소식 | 네이버 API HUB 약관이 AI 입력 금지, Daum은 뉴스 전용 API 없음 |
| 나중 | 국민연금 사업장 | 규모 참고 | 입퇴사율과 다름. 선택 기능으로 미룸 |

## 3-1. 회사 빈칸 자동화: AI 회사 조사 (2026-10-22 승인)

인재상·핵심가치·기술·고객사·최근 소식을 사용자가 손으로 적지 않는다. 사용자가 [이 회사 조사]를 누르면 Claude API의 `web_search`(검색 $10/1,000회)·`web_fetch`(토큰 비용만)로 그 회사 공식 도메인과 DART만 읽고, 인용 문장과 URL이 붙은 사실만 뽑는다. 사용자는 사실마다 맞음/틀림만 누른다(회사당 10~20초 추정). 채용 포털은 차단하고, 페이지 전체는 저장하지 않으며, 인용 없는 사실은 버린다. 추가 비용은 회사당 약 $0.05~0.10(추정).

| 빈칸 | 채우는 곳 |
| --- | --- |
| 인재상·핵심가치 | AI 회사 조사(회사 홈페이지) |
| 주요 고객사·제품 | DART 사업보고서, AI 회사 조사 |
| 쓰는 기술 | 공고 기술 키워드, DART 연구개발 항목, AI 회사 조사 |
| 최근 소식 | DART 수시공시, AI 웹 검색 결과의 제목·날짜·링크 |

## 4. 기능 목록 (단계 5 초안)

| ID | 기능 | 핵심 수용 기준 |
| --- | --- | --- |
| K-0 | 결정·정책 | AI 용도에 "자소서 맞춤 수정" 추가 승인, 외부 LLM 전송 범위·마스킹·동의 방식 확정, 예산 상한 확정 (사용자) |
| K-1 | 경험 은행 | 자소서 → STAR 경험 추출(JSON 스키마 검증), 원문 구간 연결, 사용자 확인 전에는 작성에 안 씀. 빈 결과(R)를 채우지 않음 |
| K-2 | 회사 분석 카드 | 회사 식별(법인명·사업자번호로 동명 회사 구분), 출처·발생일·확인일이 붙은 원자 사실, 사용자 확인. 자료에 없는 칸은 null |
| K-3 | 문항과 글자 수 규칙 | 문항 원문·제한·공백 포함 여부·AI 규정 입력. 서버가 최종 글자 수 계산 |
| K-4 | 맞춤 초안 생성 | 경험 매칭 → 문항별 작성. 출력은 문장·원자 주장·근거 ID·변경 이유 JSON. 서버가 근거 ID를 허용 집합과 대조 |
| K-5 | 검사 | 결정적 검사(글자 수, 다른 회사명 잔존, 원문에 없는 수치·고유명사, 역할 확대 단어) + LLM 의미 검사(지원/미지원/모순/확인 필요). "지어낸 내용 없음"은 "미지원 주장 미검출(진실 보증 아님)"으로만 표시 |
| K-6 | 문장별 검토 화면 | 원문/수정안 나란히, 문장별 수락·거절·수정·보류, 수락 때마다 재검사, 미지원 문장이 있으면 검토 완료 불가 |
| K-7 | 개인정보 | 전송 전 마스킹(이름·연락처·타인 정보), 실제 전송 텍스트 미리보기, 동의 기록, 로그에 원문 금지, 삭제 시 연쇄 삭제, 임시 초안 30일 |
| G-5 | 게이트 5 | 회귀 예시(허위 수치, 역할 확대, 다른 회사명, 글자 수 초과, 근거 없음) 전부 통과 + 실제 1개 회사로 사용자 평가 |

## 5. AI 호출과 비용 (추정)

회사 1곳, 문항 3개 기준 LLM 6회(회사 요약 1, 경험 매칭 1, 문항 작성 3, 검사 1), 입력 약 26,000·출력 약 6,000 토큰.

- 전부 Sonnet 5.5 가정: 약 $0.11/회사
- 요약·매칭은 Haiku 5.5, 작성·검사는 Sonnet 5.5: 약 $0.075/회사
- 상한: 실행당 최대 8회, $0.20에서 중단하고 부분 실패로 표시. 매일 자동 실행하지 않고 사용자가 요청할 때만.

단가는 2026-10-22 확인값이며 실제 호출 전에 다시 확인한다.

## 6. 지켜야 할 것

- 없는 경험·수치·역할·수상을 만들지 않는다. "도왔다 → 주도했다" 같은 역할 확대도 미지원으로 본다.
- 회사 정보는 출처가 있는 사실만 쓴다. 모델의 배경지식으로 회사 정보를 채우지 않는다.
- AI 탐지 회피, 표절 검사 통과 보장, 자동 지원은 하지 않는다.
- 회사 홈페이지·뉴스를 앱이 자동으로 긁지 않는다(AGENTS.md 불변식).
- 회사 분석 단계에는 사용자 자소서를 보내지 않고, 작성 단계에는 선택된 경험만 보낸다.

## 7. 순서와 의존성

단계 5는 다음이 있어야 시작할 수 있다.

- 공고 정규화와 모집 단위(N-1), 추천 목록(F-2, A-2): 어느 공고의 어느 모집 단위인지 알아야 한다.
- LLM 어댑터와 JSON 스키마 검증(A-1): 같은 구조를 재사용한다.
- 화면(U-1).

따라서 권장 시점은 **MVP(G-3) 이후**다. 그 전에 할 수 있는 것은 키 신청(금융위 기업기본정보, DART)과 K-0 결정뿐이다.

## 8. 사용자 결정 필요

1. AI 용도 제한(조건 생성·적합도 평가·추가 탐색)에 "자소서 맞춤 수정"을 추가할지.
2. 단계 5를 MVP 이후로 둘지, MVP 범위에 넣을지(권장: 이후).
3. 자소서 일부를 외부 LLM(Anthropic API)에 보내는 것에 동의하는지, 마스킹·전송 미리보기·동의 기록 방식을 받아들일지.
4. 회사 빈칸을 사용자 사실 메모로 채우는 수동 입력을 받아들일지. 받아들이지 않으면 인재상·기술 스택은 대부분 "확인 못 함"으로 남는다.
5. 예산 상한: 실행당 $0.20, 문항 최대 3개 제안.
6. 금융위원회 기업기본정보와 DART OpenAPI 키를 지금 신청할지(둘 다 무료, 개인 가능).
