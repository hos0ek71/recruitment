작성: 2026-10-19 · 오케스트레이터(Opus 5.5) · 입력: 05-dazzajo-data-intake.md(워커 A), 06-job-intake-equivalents.md(워커 B) · Orca Run `run_a783b832155a`

## 결론

dazzajo에서 "크롤링이 아닌" 부분은 **네이버 쇼핑 공식 API(키 발급)** 하나다. 이것의 채용판은 우리가 이미 신청한 사람인·고용24 공채속보·공공데이터포털 API다. 나머지 두 경로, 제조사 뉴스 HTML 감시와 다나와 HTML·화면용 AJAX는 저장소 스스로 "제한 크롤링"이라고 적은 방식이라 우리 불변식(채용 사이트 스크래핑 금지)의 예외 근거가 되지 못한다.

## 빌려 올 설계

- 발견 → 후보 → 사람 승인 → 공개의 분리. 우리 계획의 "사용자가 가져온 공고"(붙여 넣은 잡코리아 공고) 접수함에 그대로 쓸 수 있다.
- 소스 상태: 403/429가 이어지면 PAUSED, 연속 실패 수 기록, ETag·Last-Modified 조건부 요청.
- LLM은 strict JSON 스키마로 추출만 하고 자동 게시하지 않는다. 우리 A-1·A-2 원칙과 같다.

## 빌려 오지 않을 것

dazzajo는 완전성을 확인하지 않는다(소스당 20개 상한, total 대조 없음, 네이버 첫 페이지 3~5개). 우리 수집 엔진의 "마지막 페이지까지, total과 받은 건수 대조"가 더 엄격하므로 그대로 둔다.

## 다음 행동 후보

1. 사람인 승인 결과를 기다린다. 민간 공고 범위는 여기서 정해진다.
2. 인크루트에 RSS의 개인 비상업 저장·가공 조건을 문의한다(사용자 계정으로만 가능).
3. 관심 기업 5~10곳의 채용 페이지 감시를 dazzajo 방식으로 할지는 불변식 변경이라 사용자가 정한다.
