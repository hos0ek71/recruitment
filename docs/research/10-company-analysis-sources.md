## 범위와 제품 기준

전문대 졸업 예정 신입 1명이 시스템엔지니어·서버 운영·인프라·백엔드 공고에 지원할 때 필요한 기업·직무 근거를 평가했다. 공식 개발 문서·약관·데이터셋 설명만 소량 열람했다. 계정 생성, 키 신청, API 실호출, 채용·기업 사이트 스크래핑, 브라우저 자동화, 개별 기업의 채용·홈페이지 본문 수집은 하지 않았다. API 예제 URL은 명세로만 읽었으며 호출하지 않았다.

현행 설계는 AI를 조건 생성·공고 직무 적합도 평가·추가 탐색으로 제한한다. 프로필은 조건 생성용 자유 서술이며 검증된 경력·프로젝트 증거 저장소가 아니다. A-1은 프로필→조건 JSON, A-2는 공고에 있는 정보에 한한 적합도 평가이고, 회사 분석·자소서 수정은 현재 수용 기준에 없다. 따라서 이 문서는 **추가 기능의 조사 제안**이며 현행 A-2에 회사 평판·성장률을 넣거나 필터를 바꾸는 근거가 아니다. [I1, 문서 확인 2026-10-22]

저장 권한과 외부 LLM 추론 입력, 모델 학습은 서로 구분한다. 아래의 ‘조건부 활용’은 명시된 공개 범위·이용 목적 안에서 사실을 추출하는 운영 제안이다. 명시적 AI 특약을 못 찾았다는 사실을 ‘무조건 허용’으로 바꾸지 않는다. 개인정보·담당자 연락처·키는 회사 분석 입력에서 제외하고, 사용자가 제출할 자소서에 회사 설명 원문을 그대로 재현하지 않는 방안을 권한다.

## 채택 전에 구분할 쟁점

**회사 동일성.** 공고의 고용주 법인과 브랜드·그룹·고객사를 구별해야 한다. DART는 사업자·법인번호, 고용24 기업정보는 사업자번호가 있으나 사람인 응답은 회사명과 기업 페이지 링크뿐이다. 회사명 정규화만 일치하면 자료를 자동 합치는 방식은 위험하다. 사용자 확인 또는 번호·주소 등 복수 근거가 없으면 ‘회사 연결 확인 필요’로 남기는 방안을 권한다. [D3·W1·S1, 확인 2026-10-22; 연결 규칙은 제안]

**국민연금 추이는 입퇴사율이 아니다.** 신규취득에는 납부재개가, 상실에는 납부예외가 포함되고, 고지 대상 비교 방식이라 실제 인사 이동과 다를 수 있다. 사업장 단위 자료를 법인 전체 인원으로 바꾸려면 지점·분리 사업장 연결도 검증해야 한다. 화면·AI에 ‘퇴사율 높은 회사’ 또는 ‘성장 기업’으로 자동 번역하지 말고 ‘기준월 국민연금 가입자 증감’으로 한정한다. [P1, 확인 2026-10-22; 표시 규칙은 제안]

**고용24 자격과 명세의 한계.** 개인 신청 가능은 이번 TASK 및 기존 사용자 신청 화면 확인에 근거하며, 공개 소개는 여전히 기업회원 전용이라고 안내한다. 이번에 로그인·신청하지 않아 실발급·개인 적용 약관은 확인 못 함이다. 기업 목록 명세는 회사명과 기업구분명에 `coClcdNm`을 중복 표기한다. ‘공채기업상세’ 메뉴는 있으나 상세 필드를 이번 조사에서 검증하지 못했으므로 인재상·재무·스택까지 제공한다고 확대하지 않았다. [W1·W2·I2, 확인 2026-10-22]

**네이버의 캐시 예외는 AI 예외가 아니다.** HUB 개정 공지와 기존 검색 특약 모두 AI 입력을 제한한다. 임시 저장은 기기 24시간/새 질의 중 짧은 기간, 서버 이력 조회 최대 21일 등 목적별 제한이다. 이 범위는 분석용 영구 원장이나 AI 추론·학습을 허용하지 않는다. 뉴스 기사 전문 권리도 검색 결과 권리와 별도다. HUB 공지 본문은 일반 열람 파싱에서 누락되어 공식 도메인 검색에 노출된 개정 비교표로 재확인했다. [N3·N4, 확인 2026-10-22]

**수동 입력의 역할.** 기존 잡코리아 매일 검색 결과 붙여넣기는 사용자 결정으로 하지 않는다. 여기서 제안한 것은 지원 후보 하나를 분석할 때 필요한 최소 회사·직무 근거를 사용자가 선택적으로 제공하는 별도 방식이다. 자동 URL 미리보기·홈페이지 본문 요청을 붙이지 않고, 금지된 검색 API 결과를 사용자가 복사해 넣게 해 약관을 우회하지 않는다. 각 회사 홈페이지의 포괄 저장·외부 LLM 허락은 이번 조사 범위에서 확인 못 함이다. [I2·N3·N4, 확인 2026-10-22; 방식은 제안]

## MVP에 넣을 최소 조합

다음은 **제안**이다. 현행 MVP 범위를 바꾸거나 구현을 시작한 것이 아니다.

1. **기본 입력은 선택한 공고의 모집 단위 + 사용자 사실 메모.** 사용자가 직접 확인한 담당업무·필수/우대 기술, 회사의 사업·가치 중 필요한 사실만 받는다. 회사 URL·공고 URL·확인일·관련 모집 단위를 함께 남기고, 원문 저장·외부 AI 사용이 허용된 자료에만 원문 입력을 허용한다. 제목·키워드뿐이면 ‘상세 업무 확인 필요’로 남기고 분석을 꾸미지 않는다. 자소서의 개인 경험·성과는 본인 제공 근거만 쓰는 별도 입력이 필요하다. [S1·S2·I1에 따른 제안]
2. **자동 회사 기본정보는 금융위 기업기본정보 한 개부터.** 비외감 법인까지 포함하는 원천이어서 대기업~중소 법인 모두의 기본 사실을 보강할 후보로 가장 먼저 검증한다. 키 확보 후 사용자 선택 회사 소량을 수동 대조하고 번호·주소가 맞지 않으면 병합하지 않는다. 소기업 공백은 수동 사실 메모로 남긴다. [F1·F2에 따른 추정·제안]
3. **공시 대상 회사에만 DART를 선택적으로 추가.** 기업개황으로 동일성을 확인하고 최신 사업보고서·관련 공시의 필요한 사실만 추출한다. 모든 추천 공고를 매일 기업 분석하지 않고 사용자가 지원 후보를 고른 시점에 갱신하는 방안을 권한다. DART가 없다고 회사를 평가절하하거나 추천에서 빼지 않는다. [D1~D4·I1에 따른 제안]
4. **고용24 공채기업정보는 기존 신청과 함께 조건 확인 후 보강.** 키·이용 목적·AI 입력 조건이 확인되면 기업소개를 더하되 소규모 SI·SM 커버리지 해결을 맡기지 않는다. 국민연금은 이후 ‘규모 참고’ 선택 기능으로 미루고 자동 퇴사율·평판 분석은 넣지 않는다. [W1·W2·P1·I1에 따른 제안]
5. **뉴스 API와 기타 기본정보 API를 첫 버전에 늘리지 않는다.** 네이버는 AI 입력 금지, Daum은 권한 미확정이다. 국세청 상태조회는 자소서 타겟팅 가치가 낮고 강소기업 API는 개인 자격이 확인되지 않았다. 최근 소식이 없으면 확인 못 함으로 남긴다. [N3·N4·K1~K3·T1·W2·W3에 따른 제안]

최소 산출물은 ‘회사 전체 평가’보다 **출처가 연결된 회사 사실 몇 개 + 해당 직무 요구 몇 개 + 사용자의 실제 경험을 연결한 수정안**으로 잡는 편이 적합하다. 근거 없는 고객사·스택·가치·성장 주장은 생성하지 않고, 자료 부족을 드러내는 별도 기능으로 설계한다. [위 표와 I1에 따른 연구자 제안]
